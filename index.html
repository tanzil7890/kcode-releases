02 drive

This is KoraCode

It drives a real browser by writing code

Most browser agents choose from a fixed menu of clicks and keystrokes. KoraCode's agent writes JavaScript and runs it against the page through the Chrome DevTools Protocol. It copes with any site, reads exactly what it needs, and keeps the code that worked in .kcode/agent-workspace/ for next time.

your chrome

The Chrome you're logged into

Your cookies, tabs, and sessions. Turn on remote debugging once and approve the connection.

a clean chrome

A fresh profile of its own

For unattended work and for testing the app on your localhost, with nothing of yours in it.

a cloud browser

Anchor, Browserbase, Hyperbrowser, Steel, or Kernel

Pick one with /browser. KoraCode starts it, streams it, and stops it when you're done.

04 remember

The first run thinks. The runs after it just run.

When a task works, KoraCode saves what the agent did to the page as a readable script. A replay takes about a second and calls no model. If the site changes, the replay stops at the step that broke, the agent finishes the job, and the fix goes into the script.

05 repeat

Long jobs, built as graphsexperimental

Split a long job into steps you connect like a flowchart. Describe it to the agent in KoraCode Studio and it builds the graph, or draw it yourself. Every step's result is saved, so a run picks up where it stopped after a crash or a closed laptop.

Waits for you

A login, a captcha, or a decision pauses the run until you answer, then it carries on.

Fixes its own runs

Ask the chat to run it. When a run fails, the agent finds why, fixes the step, and runs it again.

Runs on a schedule

kcode daemon keeps runs and schedules going with every terminal closed.
