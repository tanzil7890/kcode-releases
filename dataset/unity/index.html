Types of data

Environments

Unity projects with a task, such as making a door open when the player walks up, and a grader that checks the scene, runs play-mode tests, and builds the project.

For
Reinforcement learning with checkable rewards
Format
Unity projects, task specs in JSON, tests per task

Trajectories

Every editor action and code change, with the Hierarchy, Inspector, and Console after each step, and the reason for it.

For
Fine-tuning and step-level rewards
Format
One JSON file per run, with scene state, code diff, and a screenshot per step

Human feedback

What a developer approved, changed, or reverted, with the diff and the reason.

For
Preference training on code and scene changes
Format
One JSON line per review, with the diff

Evals

Private tasks, refreshed every quarter, scored by tests, scene checks, and a clean build.

For
Clean measurement no model has trained on
Format
Run by us against your model; you get a scored report

One record

A trajectory is one JSON file, with the scene state, any code change, and a screenshot for every step.

How a record is made

  1. Real work

    A developer or an agent works in the Unity editor, and a developer reviews the result.

  2. Recorded

    Every editor action and code change is kept, with the console and play-mode results.

  3. Cleared for use

    Client code, assets, and keys are removed, or licensed by their owners.

  4. Graded

    Play-mode tests run and the project builds, so every record has a verified result.

Privacy

  • Every project is made for the dataset or licensed by its owner.
  • No personal data, credentials, or keys are delivered.
  • Client code is included only with written permission.
